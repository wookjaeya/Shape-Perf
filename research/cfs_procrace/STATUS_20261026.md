## 2. 아키텍처 (SPEC rev 1.4, ADR-059)

분석기 하나에 실행 계열이 둘이다. 두 계열은 같은 사건·제어 의미를 쓰고, 기록은 중립 사건 계층에서 만난다.

| 구성 | 내용 |
|---|---|
| 공통 분석 | Φ 프로필, `kz-static`(코어+적재 `.so` 결합 닫힘, 파생 빌드 B′), `kz replay`, `kz predict`(기록–모델 적합성 검사 포함) |
| 공통 의미 | `kairos/docs/event_semantics.md`: 사건 정보, 순서 근거 4종(런타임 내부 순서는 HB 아님), 보류 규칙 `kzp-hold 1`, 실현 제어 기록, 보류 가능 문맥 |
| 기록 형식 | 개정 3: 중립 사건 계층(섹션 100–107, 명시적 little-endian). 기존 F0 기록은 그대로 읽고, 변환해도 재생 결과가 같음 |
| F0 계열 | 재계측하지 않은 기준 빌드. uprobe·tracefs 관측, `kz hold`(ptrace + 디버그 레지스터) |
| 계측 계열 | GCC plugin `kzgcc` 0.2 + 런타임 `kzrt` 0.3.0(POSIX adapter, OSAL adapter는 단위 시험까지). site 목록 `kzs-sites 2`(정체성 읽기 포함), dump 1.3, `kz convert`, `kz rtplan`. 한 바이너리에서 모드로 G-I0(off)·G-I(기록)·G-I-H(기록+보류) |
| 시험 | 기본 빌드 179 중 178 통과, LLVM 빌드 201 중 200 통과(각 1개는 tracefs 조건부 건너뜀), plugin 14/14, OSAL 런타임 60/60. 시험 수는 구현 품질 확인용이며 사례 표본이 아님 |

컴파일러 연결부 후보 비교 (같은 C1·R2 관측점, 각 1회 기동):

| 후보 | 결과 | 판단 |
|---|---|---|
| GCC plugin | C1·R2 값이 F0와 같음. 계측 안 한 객체는 바이트 동일 | **주 구현** |
| Clang 소스 변환 → gcc | C1 같음. R2 해당 지점 전송 11건(24와 다름, 원인 미분리). 매크로 안 오류 반환 미계측 | 보류 |

## 3. 사례별 결과

### 3.1 R2 (cFE v7.0.1)

| 기록 | 발생 | 위반 (AppID 0 전달) | SB 자기 전송 | 다른 task 사용 | 관계 |
|---|---|---|---|---|---|
| F0 pilot3 | 269 | 24 (ES 20 + EVS 4), 직접 포획 | 5 위반 없음, 관측 상태 + A-OWNER | 240 위반 없음, 반환 코드 좁힘 | 코어–앱 264, 같은 앱 5 |
| 계측 G-I (1회) | 272 | 24, 같음 | 5, 같음 | 243, 같음(차이는 task별 전송 수) | 코어–앱 267, 같은 앱 5 |

24건은 한 경로의 호출 발생 수이며 버그 24개가 아니다. R2의 계측 실행은 빈 상태에서 시작해 F0 pilot3의 시작 상태와 다르다(결정 대기).

### 3.2 C1 — F0 계열 (CF `281a941`/`833fdbb`, BP `b051eb0`, cFS 후보 `1df262a`·`1b0b338`)

| 라벨 | 경로 | 판정 |
|---|---|---|
| 자연 (tx·rx) | 수정 전: 조회 실패 → CF 종료 | `NOT_READY_UNJUDGED` → `INCONCLUSIVE(caller_requirement_absent)` |
| 자연 (tx·rx) | 수정 후: 1회 실패 → 재시도 성공, BP1 첫 조회 성공 | `TOLERATED` → `READY`, `READY` |
| 제어 (P-C1HOLD) | 수정 후, BP를 생성 직전 보류: 25회 소진 → 종료 (E-06, BP1판 W6, W10) | `OBSERVED_VIOLATION` (`timeout-exercised`) |

## 5. 보여 준 것과 보여 주지 않은 것

- **보여 줌**: 실제 cFS 기록에서 호출 목적·자원·앱 귀속을 갖춘 판정. C1의 순서 의존과 소진 위반을 같은 바이너리·설정의 제어 실행으로 확인. 계측 계열이 F0와 같은 판정·제어를 재현하고, 일부 판정에 반환 코드와 독립인 근거를 추가.
- **보여 주지 않음**: 자연 실행에서의 빈도·발생 가능성, 새 실패 기전, 계측의 관측 효과 크기(hook 비용 미측정, 군 비교 미실시), 기존 방법 대비 기여(H4), 다섯 사례 일반성(H5).
- 주의: E-06의 위반은 채택한 요구·허용 모델의 판정이다. PR #342가 재시도 상한을 의도적으로 두었고, 강제 보류로 만든 소진은 새 운영 결함이나 자연 빈도를 뜻하지 않는다. 계측 결과는 계측 경로·컴파일러·런타임·계획을 명시한 범위에서만 유효하고, "원 바이너리에서 관측" 주장은 F0에만 쓴다.
