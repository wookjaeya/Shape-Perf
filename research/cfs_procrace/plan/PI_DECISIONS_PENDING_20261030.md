### B3. cFE 표 서비스 의미(L-TBL)를 도구 내부 지원으로 둘지

| 선택지 | 내용 | 결과 |

| (가) 넣지 않음 | C1 키는 관측 값으로 확정한다(R5) | 사람 지식이 늘지 않는다. C1의 정적 관계는 "구획 일치"로만 나와 후보가 넓다 |

- **막는 것·시점**: 막는 것은 없다(T2는 "키 미해결"로 통과 가능). 단계 4의 C1 후보 수에 영향이 있다. 기다려도 된다.

  - [F] RV2 보강 가설: 사례별 의존성·오류 조건을 입력하지 않고 실제 cFS 구성의 소스·빌드 정보·실행에서 앱 간 의존성과 근거를 추출할 수 있다. 그 정보로 후보를 찾고 일부를 확인할 수 있다(RV2 L26). "아직 주장 불가": 완전 자동 탐지 구현 완료, 다섯 사례 모두 탐지 가능, 모든 기존 기록 재사용(RV2 L544).
  - [F] SPEC 반증표 넷째 줄 "규칙이 다섯 사례에 맞춰진 것이 아님"(SPEC:870)은 두 가설에 모두 남는다.
  - [F] 외부 도구 실행 비교는 N1 보류다(PD29:20).
  - [I] RA는 실무상 RV2 가설을 따른다(RA:9). PI가 채택한 기록은 없다.

| 선택지 | 내용 | 결과 |
|---|---|---|
| (가) RV2 가설로 교체 | 기존 도구와의 차이는 H4 적용성 분석(PD29 D6) 범위의 보조 주장으로 내린다 | 10-29 지적과 바로 맞는다. 외부 실행 비교가 보류여도 핵심 주장이 선다 |
| (나) 둘 다 중심 | 추출·확인 가설과 기존 도구 차이 가설을 함께 둔다 | 주장과 반증 조건이 두 배다. 실행 비교가 보류라 둘째 가설의 근거가 약하다 |

- **막는 것·시점**: C9(SPEC), C5(RQ), 서론·기여 문단. 구현에는 영향이 없다. 평가 전에 필요하다.
- **결정하지 않으면**: SPEC은 옛 가설을 담고, 작업은 RV2 가설을 따른다. 문서와 작업이 어긋난다.

### C2. 지원 범위 선언 ("새 호출자" 기준)

- **질문**: "지원한다고 주장한 판·API 범위 안의 새 호출자에 사례 규칙이 필요 없는가"의 "지원 범위"를 무엇으로, 언제 선언하는가?
- **배경**
  - [F] RP RQ5는 "새 사례에 변경 0줄이어야 탐지"였다(RP:184). RV2는 이 보편 기준을 지우고 위 기준을 핵심으로 남겼다(RV2 L460). RA가 받아들였다(RA:35).
  - [F] RV2: 우선 지원할 코드 구조를 명확히 한 뒤 그 범위 안에서 자동 추출을 검증한다(RV2 L272).
  - [M] 지금 분석 빌드는 C1 pre/post(번들 1df262a), R2 core, C5 6.4.1/6.4.2다(S2:20).
  - [I] 범위를 결과를 본 뒤 정하면 "범위 밖이라 실패가 아니다"로 기준이 반증 불가능해진다. 선언 시점이 내용만큼 중요하다.

| 선택지 | 내용 | 결과 |
|---|---|---|
| (가) 판 단위 | 지금 빌드의 cFE/OSAL 판과 그 안의 모든 OSAL 객체 형, cFE ES/SB/EVS 기본 API를 범위로 선언한다 | 정상 대조(T6)와 맞는다. 다른 cFE 판은 범위 밖으로 명시된다 |
| (나) 코드 구조 단위 | 경로 A(등록 표 검색·키 비교), B(공유 필드 → 호출 인자 → callee 검사), C(생성·등록·소유)를 지원 구조로 선언한다 | 주장이 일반적이다. "구조 인식 실패"와 "범위 밖"을 가르는 규칙이 따로 필요하다 |
| (다) (나)를 주장으로, (가)를 시험한 판으로 | 둘을 함께 선언한다 | 일반적 주장과 검증된 범위가 분리되어 보고된다 |
| (라) 선언 없음 | 변경 줄 수만 보고한다 | RV2 §9.1의 핵심 기준을 판정할 수 없다 |

- **권고**: (다). 선언은 규칙 동결(C3) 전, 평가 집합을 고르기 전에 커밋 해시와 함께 한다. 선언 뒤 범위를 넓히면 새 판으로 기록한다. C2처럼 앱 내부 late-init 의미가 필요한 것은 범위 밖으로 명시한다(RV2 L408). "구조 인식 실패"와 "범위 밖"을 가르는 규칙을 선언과 함께 적는다.
- **막는 것·시점**: T6 정상 대조의 해석, 단계 6의 "사례 전용 지식이 남았는가"(RV2 L457), 논문의 주장 범위. 동결 전에 필요하다.
- **결정하지 않으면**: 새 호출자 기준을 판정할 수 없다. 평가는 "알려진 다섯 사례 중심"으로 한정해 보고한다(RV2 L444).

### C3. 일반화 근거와 규칙 동결

- **질문**: 다섯 사례(개발·회귀 집합) 밖의 일반화 근거를 무엇으로 삼고, 규칙 동결 시점과 동결 뒤 대상 선정자를 어떻게 하는가?
- **배경**
  - [F] RV2: 다섯 사례는 설계자가 이미 알므로 개발·회귀 집합이다. 일반화 근거는 같은 판의 다른 호출자·정상 경로, 규칙 동결 뒤 고른 구성·모듈·판, 설계에 쓰지 않은 실제 이슈에서 얻는다. 못 얻으면 "알려진 다섯 사례 중심의 평가"라고 적는다(RV2 L433–L444).
  - [F] 합성 코드는 추출기·정체성·동기화의 단위 검증에 한정한다(RV2 L478).
  - [F] D8/P-RECALL(10-15)은 "다섯 사례 먼저, 추가 평가는 별도"로 정했다. 변이 연산자·이력 질의·질의 실행자 등은 미결이다(PID:403–PID:405).
  - [F] 이미 본 대상은 A5의 배경과 같다(ED:117, ED:649, ED:672).

| 선택지 | 내용 | 결과 |
|---|---|---|
| (가) 같은 판의 다른 호출자 | T6 꼴 정상 대조를 근거로 쓴다 | 값싸다. 설계에 쓴 코드 기반이라 독립 근거가 약하다. non-blind 표시가 필요하다 |
| (나) 동결 뒤 고른 실제 구성·모듈·판 | 같은 cFS 계열의 다른 공개 앱이나 다른 cFE 판 | 근거로 강하다. 빌드·조건 기록 비용이 든다. 조건은 그 구성의 공식 문서·cmake sample에서 정한다(CP:9) |
| (다) 설계에 쓰지 않은 실제 이슈 | D8/P-RECALL의 이력 질의(다섯 사례 제외)를 규칙 비저자가 실행·선정한다 | 가장 강한 근거다. 이슈마다 수정 전·후 빌드가 필요해 비용이 크다 |
| (라) 변이 | D8의 변이 연산자로 만든 변이체 | RV2 L478에 따라 보조다. 결과는 변이 집합 한정으로만 보고한다 |
| (마) 추가 평가 없음 | 다섯 사례 중심으로 한정 보고한다 | 일반성 주장을 할 수 없다(RV2 L444) |

- **권고**: (가)를 정상 대조로(non-blind 표시), (다)를 주 근거로, 가능하면 (나) 하나를 더한다. (라)는 보조다. 동결 시점은 "단계 5 확인 드라이버까지 구현 + C2 선언" 뒤로 한다. 동결 기록은 규칙 판, P0 판, L0 해시, 커밋이다. 질의·선정은 규칙 작성자가 아닌 사람이 한다. **PI가 정할 것: 선정자(PI 본인 또는 PI가 지정한 비저자)**.
- **막는 것·시점**: 단계 6 동결 평가 전체. 평가 전에 필요하다. 노출 기록(A5)은 지금부터다.
- **결정하지 않으면**: 모든 대상이 non-blind로 남고, 논문은 "알려진 다섯 사례 중심 평가"로 한정된다.

### C4. 참·거짓·미확인의 정의와 정밀도 보고

- **질문**: 후보마다 참(위반 확인)·거짓(오탐 확인)·미확인을 무엇으로 정하고, 정밀도와 집계를 어떻게 보고하는가?
- **배경**
  - [F] RV2: 보고 단위를 호출 수·후보 관계 수·독립 원인 수로 나눈다. 반복 조회 25회나 R2 호출 24회를 독립 버그로 세지 않는다. 확인 실행 실패를 자동으로 오탐에 넣지 않는다. 전체 N을 모두 검토해 T·F·U로 나눴다면 전체 정밀도 범위는 T/N부터 (T+U)/N까지이고, T/(T+F)는 판정 완료 후보의 비율일 뿐이다. 일부만 골랐다면 선택 기준과 편향을 공개한다(RV2 L462–L471).
  - [F] 위반 근거는 "관측된 실패 결과 + 반대 순서 실현 가능성, 또는 실현된 강제 순서"다(RV2 §5.4 L341–L351, ED:528). 확인 실행 결과는 일곱 가지이고, 뒤 다섯 가지를 "무해"로 단정하지 않는다(RV2 §3.8).
  - [F] RA §3.1의 결과 뒤집힘 신호는 후보 신호이고 판정이 아니다(RA:44, RA:51). ED는 이를 별도 칸으로 뒀다(ED:519–ED:529).
  - [I] RV2는 "거짓(F)"이 무엇인지 정의하지 않는다. 정의가 없으면 거의 모든 후보가 U로 남아 범위가 0~1에 가깝게 벌어진다.
  - [F] 규모의 신호: 원형 관측점 규칙만으로 C1 OP-B가 1,131개다(ED:36). 실제 relations 행 수는 2a 뒤에 나온다 [U].

| 선택지 | 내용 | 결과 |
|---|---|---|
| (가) 좁은 F, 전수 검토 | F = (i) 정적 "불가 증명"(must 잠금 정체성, 생성·대기 직렬화로 반대 순서가 실행 불가), 또는 (ii) 반대 순서를 실현했는데 사용 u의 결과 분기가 바뀌지 않음. T = RV2 §5.4 근거. 나머지는 U. 전수 검토하고 T/N~(T+U)/N을 보고한다 | 정의가 기계적이고 사람의 의도 판단이 들어가지 않는다. 후보가 많으면 비용이 크다 |
