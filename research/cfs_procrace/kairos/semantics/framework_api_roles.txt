# framework version of the analysed builds, the API that plays each role of the method's stop event:
#   run-loop  the call an application makes in its main loop to learn whether it is to go on
#   app-exit  the call by which an application ends itself
# One entry per role per version.  An entry names the function, its definition (file relative to the tree root, line,
# sha256 of the file at the pinned revision) and its declaration in the version's public header (file, line, sha256).
# The generator applies an entry to a build when the build's facts hold the definition file with that sha256 and define
# the function on that line; it plans the entry of the function (one callee-side site per role).  The versions are told
# apart by the definition file's sha256.  Provenance: every entry is in the output of the mechanical scan of the public
# headers (research env/tools/framework_scan.py scan), and the check (framework_scan.py check) passes.  Which declared
# function plays a role is read from the header's documentation of it (the brief line the scan prints).  This file is
# data, not code: it names no case and no other file.
