### 3.2 C1 (CF `281a941` 수정 전 / `833fdbb` 수정 후, BP `b051eb0`)

빌드 4개(cFS 후보 `1df262a`·`1b0b338` × 수정 전후). 이식 변경은 경고 강등 `-Wno-error=restrict` 하나(P5: 소스·설정 미수정, 동등성 주장 안 함). 공개 구성은 CF 생성 요청이 BP보다 먼저다.

| 라벨 | 경로 | 판정 | 근거 |
|---|---|---|---|
| 자연 (tx, rx) | 수정 전: CF 조회 실패 → 종료 | `NOT_READY_UNJUDGED` → `INCONCLUSIVE(caller_requirement_absent)` | 반환 코드 |
| 자연 (tx, rx) | 수정 후: 1회 실패 → 재시도 성공, BP1 첫 조회 성공 | `TOLERATED` → `READY`, `READY` | 실패는 반환 코드, 성공은 RF 포함 상태 재생 |
| 자연 | BP 생성 전 존재 확인 | 요구 대상 아님 | 역할 선언 |
| 제어 (P-C1HOLD) | 수정 후, BP를 생성 직전에 보류: CF 25회 소진 → 종료 (E-06; BP1판 W6, W10) | `OBSERVED_VIOLATION` (`timeout-exercised`) | 반환 코드 (P11 대안이면 보류 순서) |
| 제어 (연구자 개입) | 수정 전, CF를 조회 직전에 보류 → BP 생성 뒤 해제: 조회 성공, CF 초기화 | `READY` | RF 포함 상태 재생 |
| 제어 (연구자 개입) | 예측 후보 W2·W5·W7·W8·W11·W12·W13 (BP1만 미준비, 3번째 시도 성공, 두 키 재시도 등) | 모델 재판정과 횟수까지 일치 | 일부 순서는 보류가 아니라 스케줄러가 냄 |

- 예측: 수정 전 기록 89 상태 / 후보 3, 수정 후 8,393 상태 / 후보 13 (상한 안에서 완결). 관측 간선을 고정하면 E-06 후보가 사라지고, 간선만 빼고 결과를 남기면 실현 불가능한 순서가 나와 재생이 거부한다.
- 확인 실행: confirm1 56회 + confirm2 36회. 반대 결과 0, 안전장치 발동 0. 실행 전 계획 점검이 결과를 예고했다(강제 계획 모두 실현, 실현 불가 계획 모두 정체).
- 확인 범위(정정 2026-10-26, IR §2.2): confirm2 로 고른 계획 9개(pre W2, post W1·W5·W6·W7·W8·W10·W11·W12)가 36회(9 × 4 인스턴스)에서 실현됐다. pre W3·post W13 은 confirm1 에서 확인됐다. post W2·W3·W4 는 완결된 확인이 없다(confirm1 에서 제어 원인으로 실현 안 됨, confirm2 에서 돌리지 않음). 따라서 "예측 후보가 모두 실현"이 아니다.
- 기대 결과표(동결): 나온 행은 모두 일치. 표는 고치지 않았다.

## 4. 보여 준 것과 보여 주지 않은 것

- **보여 줌**: 실제 cFS 기록에서 호출 목적·자원·앱 귀속을 갖춘 판정. C1의 순서 의존과 소진 위반을 같은 바이너리·설정의 제어 실행으로 확인. confirm2 로 고른 예측 계획 9개를 36회에서 계획대로 실현(post W2·W3·W4 는 미확인; 정정 2026-10-26).
- **보여 주지 않음**: 자연 실행에서의 빈도나 그 순서의 자연 발생 가능성. 반환값과 독립적인 미준비 판정. 새 실패 기전. 기존 방법 대비 기여(H4). 다섯 사례 일반성(H5).
- 주의: E-06의 위반은 채택한 요구·허용 모델의 판정이다. PR #342가 재시도 상한을 의도적으로 두었고, 강제 보류로 만든 소진은 새 운영 결함이나 자연 빈도를 뜻하지 않는다.
