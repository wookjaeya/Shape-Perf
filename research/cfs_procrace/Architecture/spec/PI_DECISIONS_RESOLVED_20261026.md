## 2. 채택 (IR §17, §14, §15)

1. 기존 분석기(Φ, `kz replay`, `kz predict`, `kz-static`)와 F0(재계측하지 않은 기준 빌드)를 유지한다.
2. 계측 계열을 추가한다. 구현 단위는 **컴파일러 연결부 + 공통 C 런타임 + 기본 primitive adapter**(정체성·시계·잠금·대기)다. 대상에는 관측·제어 런타임만 두고 재생·예측·보고는 호스트에서 한다. 이 계열의 근거는 코드가 실제로 쓴 값(호출 지점 인자, 성공 경로 out-parameter store의 operand)의 직접 포획, 컴파일 시점의 site 결합(바이너리 주소·앵커 해석이 필요 없음), 디버그 레지스터·ptrace 한계 없는 제어다(`plan/instrumentation_selection_20261026.md` §2, `plan/results_instr_pilot_20261026.md` §8, `plan/results_instr_gate_20261026.md` §7).
3. 컴파일러 연결부 후보는 GCC plugin(첫 후보), Clang AST 소스 변환 → GCC 빌드, LLVM 전용 pass다. 같은 C1·R2 관측점에서 IR §15.1의 일곱 질문으로 비교해 주 구현 하나를 고른다. 세 완성품을 만들지 않는다. 고르는 규칙은 IR §15.1의 세 줄을 따른다.
4. MLIR은 검토 대상으로 복귀하되(2026-10-15 D6의 조건부 재검토), 동적 계측의 선행 조건이 아니다. IR §15.2의 네 가지 중 구체적 개선이 보일 때만 도입한다.
5. `.kzt`·`.kzh`의 현재 byte layout을 그대로 고정하지 않는다. 사건·정체성·손실·제어 의미를 먼저 정의하고, 기존 기록을 읽을 수 있는 버전 변경으로 구현한다. 백엔드 원시 근거(perf 레코드, 레지스터 fetch, DR 배치)는 확장 정보로 남긴다. 저장 byte order는 명시적으로 직렬화한다.
6. "재계측하지 않은 기준 바이너리에서 관측한다"는 주장은 F0 경로에 한정한다. 계측 결과는 경로·컴파일러·런타임·계획을 명시해 범위를 적는다(IR §12.1 표). 계측 때문에 사라진 순서도 결과로 다룬다(IR §12.2).
7. 진행 순서: C1·R2 관측 대조 → 대표 confirm2 제어 대조 → 다른 사례 → C3 조건 검증.
8. 논문 기여는 컴파일러 이름이 아니라, cFS의 실제 공유·의존 관계에서 필요한 순서 근거를 확보하고 판정·확인하는 능력으로 정한다.

## 3. 대기 중이던 P11–P13 (IR §14 끝)

| ID | 결정 |
|---|---|
| P11 | 실제 보류·해제 사건을 **제어 실행에 한정한 순서 근거**로 쓴다. 원 프로그램의 동기화와 분리된 근거 종류로 표시한다. 보류만으로 관련 값의 부재가 입증되지는 않는다. 시작 상태·다른 writer·자원 세대·실제 제어 위치가 함께 맞아야 한다 |
| P12 | 예측 전의 개발 실행은 예측 뒤의 확인 실행과 구별하고 확인으로 세지 않는다. confirm2의 W1 독립 실행을 확인으로 인정한다 |
| P13 | 미해제 게이트가 남은 실행은 후보 전체의 확인으로 세지 않는다. 관측된 앞부분과 미완료 원인을 기록한다 |

## 4. 런타임·계측 설계의 필수 조건 (IR §11, §16)

- 초기화 전 관측: 정적 메모리와 최소 primitive로 기록, 정체성 미확정이면 임시 actor로 두고 나중에 근거로 연결. logger는 `CFE_ES_GetAppID` 등 대상의 불완전한 표를 다시 쓰지 않는다. 미확인 정체성을 "앱 없음"이나 AppID 0으로 채우지 않는다.
- 제어 자원: 런타임의 task·세마포어·큐가 대상 OSAL 객체 표와 용량을 쓰면 그 사실을 계상한다. OSAL 내부·초기화 전에는 private primitive 또는 비차단 관측만.
- 값: 원 명령이 실제로 쓴 값(SSA 값, 호출 인자)을 기록한다. 공유 변수를 다시 읽거나, 검증 전 포인터에 `strlen`을 부르거나, store를 atomic으로 바꾸지 않는다. Instrumentor 류의 값 교체 기능은 끈다.
- 순서: logger의 내부 순번·lock이 만든 순서를 원 프로그램 HB에 넣지 않는다. 제어가 만든 순서는 별도 근거 종류.
- 보류 문맥: gate마다 허용 문맥(일반 task / 해제에 필요한 lock 보유 / interrupt / OSAL 등록 내부 / 종료 중 / 미지원)을 명시. 미지원은 조용히 건너뛰지 않는다. 관측 callback과 blocking gate를 섞지 않는다.
- 손실: buffer overflow, 부분 기록, 초기화 전 누락, 계측 제외 코드, 미적재 모듈을 구별한다.
- 같은 빌드의 runtime mode로 비교군(G-I0/G-I/G-I-H)을 나눈다. 컴파일러 차이와 계측 차이를 한 변수로 묶지 않는다(Clang 경로는 비계측 L-A를 둔다).

## 5. 언어 규칙 예외

- 도구 핵심은 C/C++ 규칙을 유지한다. LLVM Instrumentor처럼 JSON 설정을 쓰는 외부 도구를 채택하게 되면, 그 설정은 빌드 설정 경계에만 두고 분석기 입력 형식으로 들이지 않는다(IR §14).
